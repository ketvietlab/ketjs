## Choose the system you are changing

KetJS and KetSuite share one repository but have different responsibilities. Start with the guide
that owns the code you intend to change; follow framework links only when KetSuite delegates a
contract to KetJS.

<CardGrid>
  <Card title="KetJS framework" icon="seti:config">
    Use the [framework guide](/ketjs/) for composition, data, functions, HTTP, jobs, rendering,
    themes, testing, and deployment contracts.
  </Card>
  <Card title="KetSuite application" icon="puzzle">
    Use the [application guide](/ketsuite/) for module ownership, backend UI, security boundaries,
    Channel APIs, and business-domain behavior.
  </Card>
  <Card title="Engineering reference" icon="rocket">
    Use the [operations map](/operations/) and [design records](/architecture/) when deploying,
    measuring, or changing a cross-cutting invariant.

## Follow a complete reading path

### Build an independent KetJS application

1. [Scaffold and run an application](/ketjs/quick-start/).
2. Learn [workspaces and apps](/ketjs/workspaces/) and [modules and manifest](/ketjs/modules/).
3. Add [models and scopes](/ketjs/models/), [queries and changesets](/ketjs/data/), and
   [functions and effects](/ketjs/functions/).
4. Verify behavior through [headless testing](/ketjs/testing/), then use the
   [deployment guide](/ketjs/deployment/).

### Change or extend KetSuite

1. Set up [local KetSuite development](/ketsuite/quick-start/).
2. Read the [application architecture](/ketsuite/architecture/) and place code with the
   [module development guide](/ketsuite/module-development/).
3. Choose [backend UI](/ketsuite/backend-development/) or the
   [Channel API](/ketsuite/channel-api/) for the delivery surface.
4. Review [security and data scope](/ketsuite/security-scope/) before testing with the
   [KetSuite test matrix](/ketsuite/testing/).

### Operate or evolve the platform

1. Use the [operations reading map](/operations/) to find deployment, migration, job, storage, and
   incident-related contracts.
2. Reproduce claims from the [performance benchmarks](/operations/benchmarks/).
3. Consult [architecture decisions](/architecture/decisions/) for established invariants and
   [open questions](/architecture/open-questions/) for deliberately unresolved work.

:::note[Developer documentation]
These guides describe source contracts and contributor workflows. They are not an ERP user manual.
When a development branch disagrees with a guide, checked-in source and tests remain authoritative,
and the guide must be corrected in the same change.
:::
